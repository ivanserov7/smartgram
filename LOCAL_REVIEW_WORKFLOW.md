# Правила работы с проектом

После каждой завершённой итерации, в которой изменились файлы проекта,
пересоздавай архив `~/Desktop/Smartgram_review.zip` с актуальным содержимым,
заменяя предыдущий. Обычная сборка затем автоматически передаёт проверенный ZIP
в существующую папку Google Drive для компьютера, заданную локальной настройкой
`SMARTGRAM_REVIEW_SYNC_DIR` в `.env`. Для этого используй скрипт проекта:

```bash
.venv/bin/python build_review_archive.py
```

Выполняй сборку после всех изменений и проверок. В архив обязательно включай
`AGENTS.md`, код исследования, README, зависимости и безопасный `.env.example`.
Не включай `.venv`, `.env`, другие секреты, `.git`, `__pycache__` и результаты
из `outputs`. Не добавляй настоящие ключи в `.env.example`.

Перед передачей скрипт обязан проверить `smartgram_sync_target.json` и совпадение
`drive_folder_id` с `13oz6ksdcwq8o63i67fKZcbOaOxGmoCtR`. Папку назначения не создавай
и аккаунт не угадывай. Личный путь хранится только в `.env`, пример настройки пустой.

В Google Drive сохраняй версии `Smartgram_review_YYYYMMDDTHHMMSSZ.zip` (UTC).
Не перезаписывай и не удаляй прежние версии. После проверки ZIP, размера и SHA-256
копии атомарно обновляй `latest.json`; при ошибке прежний указатель должен остаться.
Не настраивай синхронизацию всего рабочего стола/документов, расписание или наблюдатель.
Передачу ZIP запускает только сборка. `--no-sync` допустим для отдельных локальных тестов,
но не заменяет обычную финальную сборку после завершённой итерации.

Если сборка или передача не удалась, явно сообщи об этом пользователю и различай
эти ошибки: сбой передачи не удаляет исправный архив на рабочем столе.
Не утверждай, что передача завершена, если команда завершилась ошибкой.
Различай проверенное локальное копирование и облачную синхронизацию: наличие ZIP
в локальной папке Google Drive само по себе не доказывает загрузку в облако.

Все готовые HTML-отчёты для пользователя также передавай в ту же проверенную папку.
Команды `research_batch.py`, `research_report.py`, `result_page.py`, `review_gallery.py`, `script_batch.py` и `voiceover_batch.py`
делают это автоматически после создания итогового HTML. Чистые функции построения
страниц не копируют файлы: если создаёшь отчёт программно или вручную, обязательно выполни:

```bash
.venv/bin/python html_report_sync.py --report ПУТЬ_К_ОТЧЁТУ.html
```

Копируй только выбранный автономный HTML, а не папку `outputs` целиком. Не передавай
тестовые страницы как настоящие отчёты. Проверяй маркер, отсутствие ключей, размер и
SHA-256. Сохраняй версии без перезаписи и удаления; список HTML — `reports.json`,
указатель архивов `latest.json` не меняй. Не выдавай локальную копию за подтверждение
загрузки в облако. При ошибке явно сообщай, сохраняя исходный HTML и прежний список.

Если итерация включает настоящие прогоны и HTML-отчёт, передавай согласованную пару:
сначала заверши прогоны и отчёт, затем финальные изменения документации и сборку ZIP.
Проверь, что промпты в новом архиве совпадают с инструкциями в журнале этих прогонов,
а `latest.json` и `reports.json` указывают на переданные ZIP и HTML этой итерации.
Сохраняй прежние отчёты и архивы. Формат существующих указателей не меняй.

При передаче готового HTML автоматически обновляется аналитика OpenAI через
`billing_sync.refresh_after_report`; ошибка аналитики не должна прерывать основной
результат. Суммы только из Costs API, расходы вызовов подписываются как распределение.
Неподтверждённые суммы/исторические привязки оставляй нераспределёнными с причиной.
Для ручной синхронизации используй `.venv/bin/python billing_sync.py` без новых генераций.
В Drive передавай только проверенные `analytics.json` и `billing_report.html` через
`analytics_sync.py`; указатель пары — `latest_analytics.json`. Это явное разрешённое
дополнение к HTML-передаче, а не синхронизация всей папки `outputs`. Сырые ответы,
`snapshot.json`, `scope.json`, админский ключ и `.env` не выгружай. Не заявляй, что
сайт обновлён, если подготовлены только JSON и выгрузка в Drive.

## Быстрая техническая итерация (актуально с 2026-11-01)

Одна реализация → необходимые проверки → один разрешённый ограниченный реальный
прогон → одна финальная сборка и передача ZIP. Не пересобирай архив по мелким правкам.
Для visuals-only по умолчанию компактный JSON; HTML создаётся один раз после всех тем
только по явному `--full-report`. `--report-only` строит сохранённую галерею без API.
Полные отчёты по отдельному запросу пользователя сохраняют прежние правила передачи.
В быстром пути не вызывай Costs API и `billing_sync.refresh_after_report`;
usage сохраняй сразу, сверку запускай отдельно `billing_sync.py`.
Эти правила заменяют обязательный HTML/биллинг для каждой технической итерации выше.

Дополнение к безопасному ZIP — только курируемый `review/summary.json`,
`review/visuals.json`, `review/changes.txt` и перечисленные в visuals.json JPEG
`review/selected_previews/` (до 5 МиБ всего). Без секретов, base64 и сырых ответов.
`outputs`, `.env`, окружения и кеши по-прежнему запрещены. Не включай произвольные
файлы из review. Прежние архивы и отчёты не удаляй. Финальная передача — штатным
builder с проверкой маркера, размера/SHA и атомарным latest.json.

## Ассоциативный видеоряд и резерв генерации (актуальная политика)

Для текущего MVP visual — красивый тематический видеоряд, не доказательство речи.
Согласовывай строки всех активных визуальных промптов и JSON-копий; факты речи
остаются строгими. Используй role=illustrative, обычно пустые must_show/must_not_show,
широкие запросы и полноценный crop 9:16 без полей. Не требуй схем и точной эпохи/вида.
Pexels — необязательный первый источник в FastMaterials, Wikimedia — резерв.
Ключ PEXELS_API_KEY только локальный; без него сразу Commons, не проси ключ в чате.
Не обходи квоту и не копируй каталог. Лицензия Pexels отличается от Commons.
Старые одобрения/схемы не доказывают работу новых промптов: для проверки нового
визуального запуска можно переносить только неизменённые текстовые привязки.

Последним уточнением пользователь сохранил генерацию красивых картинок как резерв
после неудачного поиска. Разрешил ТОЛЬКО для сгенерированных иллюстраций размер
1024×1536 и увеличение на 25% до 1280×1920 с последующим штатным crop 1080×1920,
без полей. Сохраняй native-исходник, SHA и запись преобразования в происхождении.
Фотографии, общие бюджеты и геометрические проверки не ослабляй. Модель/quality/n,
ограниченные попытки и отсутствие автоматических повторов API сохраняются.
Одна финальная сборка с курируемым review и штатной передачей; большой HTML и
Costs API в быстром визуальном запуске не обязательны.

## Монтаж готовых материалов без повторов (2026-11-01)

В одном ролике исходник занимает один непрерывный визуальный участок. ID поставщика
и хеш исходника до кропа определяют идентичность; смена имени/кропа/зума её не меняет.
Будущий подбор исключает занятые источники во всех фрагментах, кеше, импорте и resume,
но разрешает собственное назначение и общий кеш между роликами. Неудача не резервирует
изображение и не создаёт глобального запрета. При монтаже старых материалов соседние
повторы объединяются; возврат A,B,A продлевает B. Весь звук, текст и привязки остаются.
Новый montage_plan.json хранит покрытые shot_id/fragment_index и проходит финальную
проверку, а не присваивает себе старое одобрение.

Для явного набора готовых входов используй production_batch.py --inputs-file JSON
--output ПАПКА. Маркер assembly_inputs.json запрещает поиск/генерацию при ремонте.
Готовые проверенные темы не пересобирай из-за исправления другой темы. Разметку
субтитров и silent.mp4 можно восстановить только по совместимым входам/хешам;
модельные лимиты не обнуляются. Локальные переносы используют реальные метрики
шрифта; разделение блока допустимо только на подтверждённой границе слов без
изменения таймкодов и ослабления ограничений.

MP4 передавай отдельно от исходникового ZIP через release_sync.sync_videos:
проверенный существующий Drive-каталог, новая папка версии, атомарные копии,
размер/SHA-256, компактный assembly_status.json с атрибуцией. Прежние версии сохраняй.
Не копируй outputs целиком и не заявляй подтверждённую облачную загрузку.
