# Smartgram на Timeweb

Сайт: https://smartgram.pro. Панель и HTTPS сохраняют прежнюю структуру и аккаунт.

Текущий этап: проверка согласованного выпуска. Исходники Mac сохранены,
медиа перенесены с проверкой SHA-256. Codex CLI 0.166.0 авторизован через ChatGPT;
SSH alias `smartgram` работает. Владелец явно разрешил NOPASSWD только для
check/deploy/rollback/status, правило sudoers проверено. Результаты публикации,
отката и smoke-монтажа фиксируются после их выполнения.

## Работа с кодом

```bash
ssh smartgram
cd /opt/smartgram/dev
codex
```

Alias использует обычного пользователя `smartgram-dev`, отдельный SSH-ключ.
Административный вход root сохранён. Codex CLI установлен официальным standalone
installer в `~/.local/bin`, доступен и в SSH-shell. Проверить вход:
`codex login status`; при необходимости `codex login --device-auth` и завершить
браузерную авторизацию самостоятельно. Токены в чат и Git не передавать.

Если используется поддерживающее SSH приложение ChatGPT/Codex:
Settings → Connections → SSH → smartgram → `/opt/smartgram/dev`.
В текущем Mac обнаружены VS Code и расширение Codex; отдельное desktop-приложение
в /Applications не найдено, поэтому добавление проекта в его UI не подтверждено.
Терминальный вариант выше работает независимо от этого. Переписка автоматически
не переносилась. Для Hand off нужен сохранённый проект одного Git-репозитория
на обоих хостах; текущую работающую задачу ради handoff не прерывать.

## Проверка и выпуск

```bash
cd /opt/smartgram/dev
git status --short
git add <изменённые исходники>
git commit -m 'Описание изменения'
sudo /usr/local/sbin/smartgram check
sudo /usr/local/sbin/smartgram deploy "$(git rev-parse HEAD)"
sudo /usr/local/sbin/smartgram status
sudo /usr/local/sbin/smartgram rollback
```

Корневой helper принадлежит root, sudo разрешает только эти действия.
Тесты выполняются от dev-пользователя, readiness — от производственного
`smartgram-panel`. Релиз создаётся из конкретного проверенного Git-коммита,
грязная dev-копия не публикуется. Изменение зависимостей требует отдельно
подготовленного проверенного Linux-venv; публикация с несовпадающими зависимостями
останавливается. Редактировать код активного релиза или перезапускать панель
во время генерации нельзя. Drain блокирует новый приём и выбор заданий, ждёт
текущую задачу и сохраняет очередь. Предыдущий выпуск и runner-настройки сохранены;
rollback не возвращает старые пользовательские данные.

Production: `/opt/smartgram/current`, релизы `/opt/smartgram/releases/<commit>`.
Python: `/opt/smartgram/python-env`; данные `/var/lib/smartgram`, dev-данные
`/var/lib/smartgram-dev`. Панель: `/opt/smartgram-panel/current`, её очередь
`/var/lib/smartgram-panel`. Конфигурация и provider keys `/etc/smartgram`, аккаунт
`/etc/smartgram-panel/config.json`. Production-процесс работает от smartgram-panel.

## Контракт и ограничения

`web_adapter.py <каталог задания>` читает request.json версии 1, применяет тему,
30/45/60 с (диапазон ±3 с), 720×1280/1080×1920, general/teen, clear/story,
русский язык и пожелания к конкретному запуску. Вызывает существующий pipeline.
Параметры сохраняются структурированно, пользовательский текст не попадает в shell.
Readiness: `web_adapter.py --check`, локальная проверка конфигурации, зависимостей,
ключей, шрифта и хеша адаптера. Это не подтверждение нового платного прогона.

Текущий обязательный режим — субтитры включены. Значение false отклоняется
с причиной до постановки в очередь и до API: полный проверочный путь без
субтитров ещё не поддержан. Остальные поля не игнорируются. Длительность
окончательного WAV и все approvals/hash/binding остаются обязательными.

После успешных проверок адаптер физически копирует MP4 в каталог задания и
атомарно сохраняет result.json. Ошибки и остановленные задания не повторяются
платно автоматически. Новые задания владельца могут вызывать платные API;
сама миграция их не вызывает. Перенесённый принятый MP4 — импорт, а не новая
генерация по произвольной теме.

## Импорт и диагностика

История Mac сохранена побайтно под `/var/lib/smartgram/imported/mac-project`;
копирование возобновляемое, без `--delete`. Карта старых ссылок:
`/etc/smartgram/import-paths.json`; полная ведомость SHA-256:
`/etc/smartgram/import-inventory.json`. Manifests не переписываются.
`server_import.py <старый абсолютный путь> --sha256 <ожидаемый хеш>` разрешает
только явно сопоставленную ссылку внутри импортного корня. Для монтажа используются
штатные snapshot_inputs/import_manifest с сохранением исходников и approvals.

```bash
sudo /usr/local/sbin/smartgram status
# Администратор:
systemctl status smartgram-panel smartgram-panel-proxy
journalctl -u smartgram-panel -n 50
```

Короткая стадия — progress.json задания; очищенная диагностика — diagnostic.log.
Секреты, исходники и внутренний Node-порт не выдаются через HTTP.
Работа сайта/очереди не зависит от Mac; незавершённая активная задача после
аварийной перезагрузки помечается прерванной и автоматически платно не повторяется.
