# Управление Smartgram через приватный MCP

MCP не выполняет генерацию и не предоставляет shell/SQL/произвольное чтение файлов.
Сервисы сайта, VPN и очередь видео сохраняются. Основные правила публикации:
[SERVER_WORKFLOW.md](SERVER_WORKFLOW.md).

## Инструменты

| Инструмент | Действие |
| --- | --- |
| server_status | Релиз, ресурсы, фиксированные службы, VPN, очередь и готовность туннеля |
| list_runs | Сохранённые задания, ограниченная пагинация и фильтр темы |
| run_details | Причина ошибки, версии, принятие аудио и статусы изображений/монтажа |
| run_logs | Последние 1–200 строк выбранного журнала; секреты скрываются до обрезания |
| operation_status | Состояние ранее принятой административной операции |
| publish_commit | Конкретный SHA-40: проверки, drain, штатная публикация и восстановление при ошибке |
| rollback_release | Штатный откат кода с сохранением пользовательских данных |
| restart_services | Только panel, vpn, proxy; сначала дождаться активного видео |

Изменяющие инструменты имеют readOnlyHint=false и destructiveHint=true.
Обязательный UUID idempotency_key предотвращает повтор операции при повторной
доставке; возвращается operation_id. Статус нужно опрашивать отдельно. Другой
запрос с тем же ключом отклоняется. Операции сервера сериализуются с обычным deploy.
Прерванная операция не повторяется автоматически; сомнительное восстановление
оставляет приём очереди на паузе.

## Границы доступа

- `smartgram-mcp`: отдельный nologin-пользователь, loopback `127.0.0.1:18788/mcp`.
  Нет членства в группе production и прямого чтения ключей/истории.
- Единственный sudo-путь — root-owned `/usr/local/sbin/smartgram-mcp-admin` без
  аргументов, JSON с фиксированными операциями. Root-код лежит вне dev и доступен
  только для чтения. Пользователь не может подменить посредник или передать команду.
- Длинные операции исполняет фиксированный systemd worker. Нет дополнительной
  очереди видео. Данные, оплаченные материалы, версии, лимиты и approvals сохраняются.
- `smartgram-tunnel`: отдельный nologin-пользователь без sudo. Официальный
  tunnel-client v0.0.19, релиз проверяется по SHA-256; только исходящий HTTPS к OpenAI.
- MCP-порт не открывается наружу. Внутренний bearer передаётся через systemd
  credentials; внешняя доступность регулируется привязкой Secure MCP Tunnel.
- Службы: `smartgram-mcp`, `smartgram-tunnel`. Секреты: `/etc/smartgram-mcp` (0700),
  файлы 0600. Runtime key, bearer и подписка VPN не входят в Git или ответы инструментов.
  Служба MCP не выводит SDK validation traces с пользовательскими входами.

## Регистрация туннеля

Нужен отдельный Restricted runtime API key с Tunnels Read + Use. Ключ конвейера
не используется. Создать туннель в нужной Platform organization и привязать точный
ChatGPT workspace. Посредник регистрации проверяет associations через metadata GET;
лишние или несовпадающие scopes отклоняются. Admin key постоянно не хранится.

Ввод выполняется только в терминале владельца через подготовленный root-only
`configure_tunnel.py`: Tunnel ID, ожидаемые Organization ID/Workspace ID, затем
скрытый runtime key. Скрипт отказывается сохранять ключ конвейера или admin key.
Секретные данные не задаются аргументами командной строки.

В ChatGPT → подключение собственного MCP:

- Connection: **Tunnel**.
- Tunnel ID: фактический ID из `/etc/smartgram-mcp/binding.json` после регистрации.
- Authentication: **No authentication / None**. Это выбор для внешней формы;
  сам туннель требует прав аккаунта, а локальный MCP защищён внутренним bearer,
  который tunnel-client добавляет самостоятельно. Runtime API key в форму не вставлять.

Проверять отдельные состояния: клиент установлен; MCP отвечает локально; metadata
подтвердила scope; tunnel healthy/ready; ChatGPT обнаружил восемь инструментов и
выполнил read-only вызов. Установка службы не доказывает последний пункт.

Официальная инструкция:
https://developers.openai.com/api/docs/guides/secure-mcp-tunnels

## Проверки и обслуживание

`test_mcp_admin.py` работает без SDK/сети; `test_mcp_http.py` проверяет реальный
MCP SDK/ASGI с подставным broker. Зависимости MCP находятся в отдельном venv,
`requirements.txt` и Linux-окружение конвейера не меняются. CI проверяет оба слоя.

Привилегированный MCP-код обновляет администратор после проверки конкретного
коммита и хешей. Обычный deploy видео не заменяет root helper произвольным dev-кодом.
Откат видео остаётся штатным; для отключения управления остановить и отключить
`smartgram-tunnel` и `smartgram-mcp`. Сайт и конвейер не зависят от этих служб.
Секреты сохранять закрытыми, а не переносить в диагностику/архив.
