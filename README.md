# Smartgram

Конвейер коротких познавательных вертикальных видео: тема → проверенный сценарий → озвучка и изображения → субтитры и монтаж → проверенный MP4.

- Сайт: [smartgram.pro](https://smartgram.pro).
- Разработка и выпуск: [SERVER_WORKFLOW.md](SERVER_WORKFLOW.md).
- Приватное управление сервером: [SMARTGRAM_MCP.md](SMARTGRAM_MCP.md).
- Обязательные правила работы с кодом и данными: [AGENTS.md](AGENTS.md).
- История прежних реализаций: [архив документации](docs/development-history.md). Архив не определяет текущее поведение.

## Быстрый старт

Нужны Python 3.12, Node.js 24 для панели, FFmpeg/FFprobe с libass и проверенный шрифт. Python-зависимости закреплены в `requirements.txt`.

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env
.venv/bin/python main.py --topic "Почему закат красный" --dry-run
```

`--dry-run` показывает план без API и без создания видео. `--demo` использует подставные ответы; это проверка логики, а не готовый настоящий ролик. Для настоящего запуска уберите этот флаг:

```bash
.venv/bin/python main.py --topic "Почему закат красный"
```

Результаты сохраняются в отдельном каталоге запуска под `outputs/`; панель использует выделенный серверный каталог данных. Доступ к провайдерам задаётся через переменные окружения или локальный `.env`. Ключи, медиа и журналы не коммитятся. На сервере окружение находится в `/etc/smartgram/production.env`, данные — в `/var/lib/smartgram`.

| Настройка | Назначение |
| --- | --- |
| `OPENAI_API_KEY` | Исследование, сценарий, проверки, независимое распознавание речи и резервная генерация изображений |
| `GEMINI_API_KEY`, `DEEPGRAM_API_KEY` | Озвучка и таймкоды |
| `PEXELS_API_KEY` | Необязательный первый источник фото; без ключа используется Wikimedia Commons |
| `FFMPEG_PATH`, `FFPROBE_PATH`, `SUBTITLE_FONT_PATH` | Реальные локальные пути; примеры для Mac в `.env.example` нужно заменить на своём сервере |
| `GEMINI_HTTP_PROXY` | Необязательный прокси только для Gemini; [настройка](GEMINI_PROXY.md) |
| `OPENAI_ADMIN_KEY` | Необязательная сверка расходов; не нужен для генерации |

Модели, лимиты и геометрия визуалов задаются в `visuals_editing_config.json`. Текстовые промпты в `prompts/` имеют приоритет над их копиями в конфигурации.

## Как устроен запуск

| Этап | Основные модули | Результат |
| --- | --- | --- |
| Исследование | `research_engine.py`, `research_requests.py`, `research_policy.py` | Факты и источники; отдельная проверка достаточности |
| Сценарий | `script_workflow.py`, `script_requests.py` | Версионный сценарий и проверка утверждений |
| Озвучка | `voiceover.py`, `gemini_voice.py`, `voice_api.py`, `voice_alignment.py` | Один WAV, независимая проверка текста, реальные границы слов и фрагментов |
| Изображения | `fast_materials.py`, `pexels_materials.py`, `commons_materials.py`, `visual_generation.py` | Проверенные оригиналы, источники, кадрирование и превью |
| Монтаж | `editing.py`, `video_render.py`, `subtitles.py` | Видео, субтитры, технические и визуальные проверки |
| Оркестрация | `pipeline.py`, `production.py`, `production_state.py` | Состояние запуска, ограничения, возобновление и кеш операций |
| Панель | `server_infra/panel_app.mjs`, `web_adapter.py` | Вход, очередь, настоящий прогресс и выдача принятого MP4 |
| Расходы | `openai_meter.py`, `billing_*.py`, `web_analytics/` | Наблюдаемое потребление, оценки и отдельно сверенные расходы |

Озвучка и подбор изображений стартуют параллельно после принятия сценария. Если текст меняется, монтаж проверяет актуальность обеих веток. Успешные совместимые результаты переиспользуются. Deepgram отвечает за таймкоды; подтверждённый независимым OpenAI ASR текст не отклоняется только из-за ошибки Deepgram.

### Когда подходящего фото нет

1. Планировщик задаёт понятный иллюстративный кадр по смыслу сцены.
2. Конвейер ищет фото в Pexels, затем Commons, проверяет лицензию, качество, уникальность и пригодность для кадра.
3. Если подходящих фото не осталось либо закончился ограниченный поиск, используется OpenAI Images API. Текущая модель — `gpt-image-2.5-flare`, `quality=medium`, одна картинка на запрос.
4. Генерируемая иллюстрация проходит проверку и подготовку кадра. Её происхождение и потребление сохраняются; она не выдаётся за документальную фотографию.
5. Принятый оригинал 1024×1536 сохраняется отдельно. Только для него разрешено увеличение до 1280×1920 и штатный crop 1080×1920. Правила исходных фотографий не ослабляются.

Лимиты генерации и ремонта постоянны для запуска. Авторизация, квота, сбой сервиса или неизвестный исход запроса не превращаются в бесконечные попытки. Монтаж из явно переданных готовых материалов (`assembly_inputs.json`) никогда не запускает новый поиск или генерацию.

## Возобновление и готовые материалы

```bash
# Продолжить сценарий из сохранённого исследования
.venv/bin/python main.py --research-file outputs/RUN/research.json

# Продолжить подбор и монтаж принятого запуска
.venv/bin/python main.py --resume-production outputs/RUN

# Только монтаж из принятых материалов
.venv/bin/python main.py --resume-production outputs/RUN --production-stage editing

# Явный набор готовых входов: без нового поиска/генерации
.venv/bin/python production_batch.py --inputs-file inputs.json --output outputs/ASSEMBLY
```

Возобновление сохраняет использованные бюджеты и успешные операции. Незавершённый платный запрос блокирует молчаливое повторное списание; сначала нужно разобраться с сохранённой причиной. Один каталог запуска нельзя одновременно изменять двумя командами одного этапа. Историю принятых файлов и привязки к версии сценария нельзя «чинить» удалением журнала.

## Проверки перед PR

```bash
.venv/bin/python run_tests.py
node --test server_infra/test_panel.mjs server_infra/test_progress.mjs web_analytics/test_costs.mjs
```

`run_tests.py` автоматически находит `test_*.py`, включая проверки MCP-посредника `test_mcp_admin.py`. Только `test_mcp_http.py`, которому нужен отдельный MCP SDK, запускается обязательным шагом CI в изолированном окружении из `server_infra/mcp_requirements.txt`; SDK не добавляется в зависимости конвейера. Телеметрия основного набора изолирована; внешний DNS и сетевые соединения запрещены, локальные HTTP-фикстуры разрешены. CI и серверная проверка используют этот же Python-набор. Тесты не вызывают платные API. Тяжёлые проверки FFmpeg запускаются последовательно.

Изменения оформляются отдельной веткой и PR. Push в `main` после успешного CI запускает штатное обновление сервера с ожиданием активного задания. Не редактируйте production-релизы напрямую. Порядок выпуска, проверки очереди и отката — в [SERVER_WORKFLOW.md](SERVER_WORKFLOW.md).

## Разработка и диагностика

При ошибке начните с `run.json`, состояния конкретного этапа и его манифеста. Сохранённые причины отказа, ID запросов и хеши важнее статуса «картинка не найдена». Не подменяйте неизвестную стоимость нулём и не присваивайте непроверенному файлу старое одобрение.

Подробные контракты аналитики — в [analytics_schema.md](analytics_schema.md). Процесс внешнего ревью через архив используется только по отдельному запросу: [LOCAL_REVIEW_WORKFLOW.md](LOCAL_REVIEW_WORKFLOW.md). Итоги текущего аудита и пределы проверки — в [docs/code-audit.md](docs/code-audit.md).
