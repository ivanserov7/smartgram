# Аналитика Smartgram: JSON v1, revision 3

Экспорт: `outputs/billing/analytics.json` и парный `billing_report.html`.
`schema_version=1` сохранён для совместимости существующего потребителя;
`schema_revision=3` добавляет выбор факта или оценки без удаления прежних полей.
`source="OpenAI Costs API"`, `allocation_details`, `calls`, `videos`, `runs`,
`sync`, `period` сохранены. Сайт и его endpoints не менялись.

В проверенной папке Drive указатель пары — прежний `latest_analytics.json`.
Проверяйте имена, размер и SHA-256 JSON/HTML. `export_id` связывает конкретную
генерацию JSON с метатегом `smartgram-analytics-export` в HTML. Это SHA-256 JSON
без поля export_id, сериализованного через Python json.dumps с ensure_ascii=False,
sort_keys=True, allow_nan=False и стандартными разделителями. Несовместимая пара
не передаётся; прежний указатель сохраняется. Это проверка локального копирования,
а не доказательство завершения облачной синхронизации.

## Денежные факты

Суммы — точные десятичные строки по валютам: `{"usd":"0.0972952"}`.
`null` означает неизвестность, `{"usd":"0"}` — подтверждённый ноль.
Отсутствие строк Costs API не означает нулевые расходы. Двоичный float не
используется для хранения денег, распределения или проверки баланса.
Разные валюты не складываются. Подтверждённая денежная база — только Costs API.

`actual_charges = allocated_charges + unallocated_charges` отдельно по валютам.
Это одна сумма в разных представлениях: факт нельзя складывать с распределением;
нельзя складывать разрезы по роликам, этапам, запускам с итогом по вызовам.
Распределённая стоимость — **доля суточного начисления**, а не отдельное
начисление OpenAI на request_id. Старые тарифные оценки находятся отдельно
в estimates и не добавляются к факту.

ключ, маски ключей, их локальные отпечатки и .env не выгружаются.

## Журнал и доказательное восстановление

OpenAIMeter дополняет прежние *_usage.json, не заменяя журналы производителей.
Для новых обращений сохраняются video_id/run_id/call_id, provider/stage/step,
configured/actual model, параметры, подтверждённые api_key_id/project_id,
UTC/длительность, status, provider request/response IDs, исходные usage,
**tool_usage**, наблюдаемые HTTP-попытки и доступные единицы. Время сервера
created_at также сохраняется. ID ключа устанавливается только по ранее
подтверждённому сопоставлению fingerprint ↔ ID; при отсутствии доказательства
остаётся null до административной сверки. Секреты и Authorization не записываются.

Импорт читает основной outputs и существующие `.isolated/*/work/outputs`:
реальные журналы из параллельной копии учитываются без переноса её кода.
Одинаковый provider response/request ID дедуплицируется, включая связующую
запись с обоими идентификаторами. Различные реальные response IDs не сливаются
только из-за одинакового логического call_id. Исторический fallback call_id
выводится из provider ID, если он есть, и не меняется при копировании журнала.

Дополняющие копии восстанавливают поля друг друга. Противоречивые значения
не выбираются произвольно: conflicting_fields сохраняется, потребление не
используется для распределения. Доказательства в `field_provenance` включают
путь/поле исходного журнала и дополнительные источники; `source_journals`
сохраняет все копии. Старые файлы не переписываются ради восстановления.

Приоритет для UTC-дня потребления: серверный response.created_at, затем
наблюдаемое начало клиента. При наличии только явного billing_day_utc сохраняются
`time_precision="day"` и `start_time=null`; точные секунды не выдумываются.
Наивное локальное ISO-время без часового пояса не становится UTC автоматически.
Имя папки, mtime и нынешний ключ не доказывают дату/ключ старого запроса.
Без даты запись остаётся в calls и completeness, но не попадает в график времени.
Вызов после конца наблюдаемого снимка не получает его начисления. Для записи
с известными только сутками распределение ожидает завершённый UTC-интервал.

`usage`, `tool_usage` сохраняются отдельно от вычисленных `units`.
Reasoning уже входит в output_tokens и не прибавляется второй раз.
Неизвестные категории кеша не заменяются нулём. Нулевой неотрицательный итог
Usage API по всей точно совпавшей группе может доказать нулевую категорию
каждого запроса; такое восстановление имеет `unit_provenance` с ID строки API.

## Поиск

`tool_usage.web_search.num_requests` — число **оплачиваемых поисков** в ответе.
Дисконтированные поиски и действия наподобие открытия страницы в него не входят.
Отсутствующее поле остаётся неизвестным. `web_calls_observed` хранится отдельно:
число элементов web_search_call, поисковых действий, открытых страниц или
источников не подставляется вместо оплачиваемых единиц.

Официальные источники:
[Responses tool_usage](https://developers.openai.com/api/reference/cli/resources/responses/methods/create),
[Web Search Usage](https://developers.openai.com/api/reference/resources/admin/subresources/organization/subresources/usage/methods/web_search_calls),
[Costs / quantity](https://developers.openai.com/api/reference/resources/admin/subresources/organization/subresources/usage/methods/costs).
Документация проверена 1 ноября 2026 перед реальным чтением. Финальные денежные
суммы сверяются с биллингом, а не рассчитываются по цене поискового вызова.

Поддержаны model-specific `model, web_search_calls` и общая статья
`web search tool calls`. Для общей статьи необходима одна однородная группа
модели/контекста/режима Web Search Usage. Billing-модель websearch при этом
не подменяется моделью вызывавшего LLM; исходная LLM-модель остаётся у вызова.
Смешанные модели/контексты не объединяются без раскрытого деления статьи.
При quantity/unit проверяется размерность и совпадение полного объёма с Usage.
Например, quantity_unit=tokens у поисковой статьи не интерпретируется тайно как
requests: неоднозначность сохраняет остаток с причиной. Это условная проверка
доказательств, а не безусловный запрет категории поиска.

## Распределение фактических денег

Группа: точные сутки UTC / проект / ключ / статья и валюта, с моделью,
service_tier/batch и отдельной категорией input/output/cache/tool. Если статья
не назвала режим, его можно взять из единственной подтверждённой группы Usage;
несколько режимов не смешиваются. Аудио не распределяется как общий текстовый
input/output при неподтверждённом разложении цены. Неподдерживаемые статьи
сохраняют весь остаток и объяснение.

Для однородной статьи:

- A — фактическая сумма Costs;
- U — полный сверенный объём нужной категории Usage;
- u_i — подтверждённые единицы известного вызова.

Доля вызова: `A * u_i / U`. При неполном журнале знаменатель остаётся **полным U**,
а не суммой известных вызовов. Распределяется `A * sum(u_i) / U`; остальное
остаётся нераспределённым. Единицы известной категории не требуют ложного
совпадения всех несвязанных категорий или полного числа записей. Превышение
известных единиц над Usage, конфликт, несогласованная quantity или неоднородный
режим блокируют распределение статьи. Неизвестные единицы исключаются из
числителя, не считаются нулём и не получают долю чужого расхода.

Неизвестное потребление прежнего HTTP-повтора не запрещает долю подтверждённого
ответа. При этом полная стоимость логического вызова остаётся неизвестной.
`attempt_consumption` сохраняет доступный usage/tool_usage каждой попытки;
неподтверждённые расходы повторов не приписываются последнему ответу.

`allocation_details[]` содержит provider_amount, allocated_amount,
unallocated_amount, status, reason, shares и reconciliation:
provider_row_id, provider_units, known_units, category, billing_model,
service_tier/batch/context_level и источник сверки. Доли и остаток считаются
Decimal с высокой фиксированной точностью. Конечное округление детерминированно;
остаток частично известного счёта не отдаётся последнему известному запросу.

`calls[].allocation_complete=true` только когда покрыты **все** известные
положительные денежные категории, нет неясного состава/совместимой неучтённой
статьи, конфликтов или неполных прежних HTTP-попыток. Частичная сумма имеет
allocation_complete=false, allocation_categories и allocation_incomplete_reasons.
Вызов без начислений не становится бесплатным. Новые суммы перечитываются при
ручном запуске billing_sync.py; категории в pending_charges остаются null.

## Графики и средние

Даты денег — исходные суточные интервалы UTC, начало включительно, конец
исключительно. Они не перераспределяются пропорционально часам и не превращаются
в точные московские дни. Для графика по произвольным локальным суткам нет
достаточной точности Costs API. Время самого вызова можно отображать локально
отдельно, сохраняя UTC-день денежного начисления.

`time_series.day/week/month` хранит start/end UTC и фактически наблюдаемые
observed_start/end. Неделя начинается в понедельник, месяц — первого числа.
coverage_truncated=true означает неполную неделю/месяц на границе периода или
текущие незавершённые сутки. Отсутствие денежных строк в интервале — null.

Показатели каждого интервала:

- actual/allocated/unallocated по валютам;
- calls_count — число записей логических вызовов в интервале, confirmed_calls_count
  и unknown_request_observation_calls уточняют доказанность фактической отправки;
- run_count/run_ids — уникальные наблюдаемые запуски; ready_video_count/IDs —
  принятые MP4 с известным временем завершения;
- models — множество фактических model IDs, known_unique_model_count — его размер;
  unique_model_count=null при неизвестных моделях с причиной и статусом;
- tokens по отдельным категориям: value только при полном покрытии, known_sum,
  known_calls, unknown_calls, status/reason; reasoning не суммируется к output;
- errors логических вызовов, failed_http_attempts, observed_retries и
  unknown_retry_calls; нет наблюдения — не доказательство нуля повторов;
- call_duration_seconds и run_duration_seconds: известная сумма, число известных
  и неизвестных. Длительность параллельного запуска **не равна сумме вызовов**;
- average_call_cost и average_ready_video_cost: value, numerator, denominator,
  denominator_by_currency, population_count, coverage, status/reason/formula.

Средние используют только полностью учтённые вызовы/готовую когорту. Если часть
когорты неизвестна, среднее известной полной подкогорты имеет status=partial_cohort
и явное покрытие; её нельзя выдавать за среднюю стоимость всей популяции.
Неизвестная стоимость не входит в знаменатель как нулевая. Для готового ролика
расходы относятся к **выбранному периоду** связанных вызовов, не ко всей истории
жизни ролика. При неизвестной дате связанного вызова полная денежная когорта
не подтверждена. Поля общего среднего ready сохраняют прежнюю совместимость.

Для недели, месяца или произвольного диапазона нужно снова сложить исходные
суммы/счётчики полных когорт и объединить множества моделей/ID. Нельзя усреднять
дневные средние или складывать ежедневное количество уникальных моделей.
Курированные исходные billing_rows, provider_consumption, calls и runs позволяют
сделать это независимо от заранее сохранённых time_series.

## Запуски и готовность

runs[] содержит started_at_utc, ended_at_utc, duration_seconds, status,
completed_at_utc, если они явно есть в журнале. Допустимо вычислить разность
реальных границ того же запуска с provenance. Длительность видео из
render_manifest.duration_seconds не является длительностью выполнения программы.
При отсутствии жизненного цикла поля null с duration_status/reason. Время
первого/последнего запроса не подставляется вместо границ всего запуска.

Готовность: явное video_status=approved и существующий локальный MP4 либо
реальный render_manifest.status=ready + quality_report.ready + успешная
техническая часть + существующий MP4 с совпадающим сохранённым SHA-256.
Тестовые/demo-манифесты и test_video.mp4 не считаются реальным выпуском.
Время завершения берётся из журнала, не из mtime. Неизвестная дата готового
ролика учитывается отдельно, а не приписывается текущему дню.

## Свежесть и безопасная передача

CLI billing_sync.py принудительно перечитывает последние 30 дат; автообновление
после отчёта использует кеш провайдера максимум пять минут, но заново читает
локальную историю. Нормализованный снимок заменяется целиком после успешного
чтения Costs и пагинации: обновлённые начисления не добавляются повторно.
При ошибке остаётся прошлый снимок с прежней датой и текущей ошибкой.

Drive получает только проверенные analytics.json и billing_report.html через
analytics_sync.py. Проверяются маркер/ID папки, отсутствие секретов, идентификатор
пары, размер/SHA-256 обеих копий и денежный баланс. Версии сохраняются без удаления;
latest_analytics.json обновляется атомарно после проверок. ZIP использует отдельный
latest.json. Никакая синхронизация outputs целиком, отправка на сайт, новый сервер,
расписание или наблюдатель не добавлены.

## Факт при наличии, иначе оценка (revision 3)

По уточнённому требованию владельца стоимость для показа не обязана ждать
полного биллинга. `calls[].effective_cost` содержит `status` actual / estimated /
mixed / unknown, русскую `label`, `amount`, раздельные `actual` и `estimated`,
`complete`, `components`, `assumptions`, `missing`, `pricing_version`, `source_url`.
Деньги остаются десятичными строками по валютам. Факт каждой категории заменяет
оценку этой категории. Частичное распределение дополняется только оценками
недостающих категорий; неподтверждённый остаток Costs при этом сохраняется.
Неизвестный ключ/дата не мешают тарифной оценке по известному usage, но не дают
права на фактическое распределение. Неизвестные режим/кеш/TTL допускаются только
как явно записанные тарифные допущения. Без модели, тарифа или consumption —
«Нет данных», при неполной цене — «частично». Reasoning повторно не добавляется.
Наблюдаемый usage предыдущих HTTP-попыток учитывается отдельно, без usage цена
этих попыток остаётся неполной. Аудио оценивается по модальностям или явно
поддержанным секундам, а не по тарифу обычных текстовых токенов.

`effective_costs` — выбранный период; `undated_effective_costs` — история без
даты отдельно; группы videos/runs/stages также содержат `effective_costs`.
Фактические `actual_charges`, `allocated_charges`, `unallocated_charges` и
строки Costs не меняются из-за оценки. Эти поля по-прежнему подчиняются точному
балансу. Итог известных вызовов может включать факт + оценку, но никогда не
складывается с общим фактическим счётом или его нераспределённым остатком.
Тарифы оценок проверены 01.11.2026 по официальным страницам моделей и pricing;
тарифный снимок не означает историческую фактическую цену, скидку или кредит.

Офлайн-пересчёт без административного ключа и сетевых запросов:
`.venv/bin/python billing_sync.py --offline`.
Вкладка сайта и её публикация описаны в [web_analytics/README.md](web_analytics/README.md).


### Компактный основной экран

`production_summary` (совместимое дополнение revision 3): `ready_video_count` —
все уникальные проверенные готовые MP4; `average_generation_seconds` и
`timed_video_count` — наблюдаемые времена готовых запусков и покрытие;
`average_video_cost` — средняя стоимость по известной цене готовой когорты,
с раздельными средними `actual` / `estimated`, `priced_videos`, `total_videos`,
`label`, `complete`. Нет цены — ролик не попадает в знаменатель как бесплатный;
